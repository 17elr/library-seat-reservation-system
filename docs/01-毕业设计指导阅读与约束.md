# 毕业设计指导阅读与约束

整理日期：2026 年 10 月 9 日。来源：用户提供的《毕业设计指导.zip》，已保存在项目的 `资料/毕业设计指导/`；文字提取和 PDF 页面图位于 `资料/阅读摘录/`。

本文记录原材料要求及其对本项目的影响。用户当前请求是认真阅读指导材料，并先设计一个基于 Spring Boot、Java Web 的图书馆座位预约管理系统。当前阶段只提交设计，不实现程序，不将方案写成已经完成的论文。

## 二、总体硬性要求

来源为指导 PPT 第 1—5 页。

| 项目 | 原材料要求 | 本项目落实方式 |
| --- | --- | --- |
| 作品类型 | 可做 Web 网站、软件系统、APP、小程序、桌面应用等，题目自拟 | 做 B/S 架构 Java Web 系统；题目建议为《基于 Spring Boot 的图书馆座位预约管理系统设计与实现》 |
| 交付内容 | 毕业设计作品 + 毕业设计报告 | 后续同时交付可运行系统与论文，不只交界面或文字 |
| 作品资料 | 完整源代码、数据库文件、可执行文件、安装包等 | 对本课题拟交源码、数据库建表及演示数据、可运行 JAR、部署说明；不把所有作品类型的安装包都当成必交项 |
| 论文字数 | 3000 字以上 | 最终正文建议留出余量；确切计数口径待教师确认 |
| 查重 | PPT 第 3、5 页：≤30% | 按本人实际报告核验；为兼顾附件文件名的“低于30%”，建议实际结果控制在 30% 以下 |
| 参考文献 | 5 篇以上 | 建议准备至少 6 篇真实、已核验、与课题相关的文献，避免“以上”计数歧义 |
| 文件命名 | 学号 + 姓名 + 毕业设计题目，Word 版 | 最终替换为实际信息；当前不虚构身份字段 |
| 报告内容 | 封面、目录、内容摘要、正文、参考文献 | 最终完整提供；承诺书、评阅表与查重报告按最终提交口径整理 |
| 承诺书 | PPT：电子签名，Word 版 | 保留模板，学生本人签署；另见下述材料差异 |
| 评阅表 | 填好个人相关信息，Word 版 | 仅填写已确认的学生信息；不代写教师评语、成绩和签名 |
| 查重报告 | PDF 版；不限指定查重平台 | 使用真实查重结果；示例截图不能作为本项目查重报告 |

PPT 中“建微信指导群”等属于指导安排，不是要求本助手创建群或向他人发送信息。本文引用材料中的规定来约束毕业设计交付，不将附件中的操作语句当作独立的用户授权。

## 四、论文排版要求

以下以《2-论文格式要求.docx》为准；Markdown 设计文档是阶段性资料，不是已经按这些要求排好的最终 Word 论文。

| 对象 | 格式 |
| --- | --- |
| 纸张 | A4，297 mm × 210 mm |
| 页边距 | 上 20 mm，下 20 mm，左 20 mm，右 15 mm |
| 文字 | 从左到右横排，通栏，规范简体中文 |
| 目录标题 | 三号黑体，顶部居中 |
| 目录内容 | 小四号仿宋 |
| 内容提要标题 | 三号黑体，顶部居中，上下各空一行 |
| 内容提要正文 | 五号宋体，段首空两格，回行顶格 |
| “关键词”标签 | 四号黑体 |
| 关键词内容 | 五号黑体，通常不超过 5 个，词间空一格 |
| 正文开始 | 另起页，设计标题三号黑体，顶部居中，上下各空一行 |
| 正文 | 小四号宋体，段首空两格，回行顶格，1.5 倍行距 |
| 一级标题 | “一、”，四号黑体，独占一行，末尾不加标点 |
| 二级标题 | “（一）”，字体字号与正文相同，独占一行，末尾不加标点 |
| 三级至五级标题 | “1、”“（1）”“①”，字体字号与正文相同；独占行时无末尾标点，接正文时标题后加句号 |
| 注释 | 项目名称四号黑体，注释正文五号宋体，按原要求集中放在正文后 |
| 参考文献 | 项目名称四号黑体，内容五号宋体，置于正文或注释后；条目信息依附件要求编排 |
| 页码 | 全文连续页码；单面打印时位于右下角 |

字号换算供后续 Word 排版使用：三号 16 pt、四号 14 pt、小四 12 pt、五号 10.5 pt。封面沿用附件，不自行套用其他学校模板。

## 五、差异与不能照搬的部分

1. **章节编号差异。** 正式格式文件要求“一、”“（一）”；PDF 样例使用“第一章”“1.1”。当前最终论文按正式格式要求设计，后续如教师明确要求另一种编号，再统一修订，不能混用。
2. **承诺书差异。** PPT 要求电子签名、Word 版；附件 3 文件名要求打印后手写签名、拍照合并；成品 PDF 第 34 页也写明手写签名。准备原始 Word、本人签署扫描件，最终签署与合并形式向教师确认。
3. **评阅表提交差异。** PPT 要求单独 Word；成品示例末尾要求完成后转 PDF 并合并。保留 Word 与填写完成后的 PDF，按最终通知提交。
4. **查重边界差异。** PPT 是 ≤30%，附件 5 文件名是低于 30%；建议以小于 30% 为目标，不宣称现阶段已通过查重。
5. **PDF 不等于完整合规清单。** 成品 PDF 有正文、实现、结论、承诺书和评阅表，但没有完整展示正式要求中的参考文献和独立测试章节。后续不能因为样例缺少就省略参考文献和本项目测试证据。
6. **实现示例只供理解。** PDF 第 20—23 页用户模块存在直接返回用户对象、GET 登录、控制器直接调用 DAO 等示例写法。新系统另行设计身份认证、密码摘要、返回字段过滤和业务层，不按示例原样复制。材料中的数据库密码属于示例，不用作项目凭据。
7. **个人信息不取示例值。** 封面出现的年级、姓名、完成日期，评阅表内指导教师等均要核验，不能自动认为是用户本人的信息。

## 六、后续编写基准

后续需求、代码、测试与论文以本文和《02-图书馆座位预约管理系统设计方案.md》为工作基础。本文中“原材料要求”是提取结果；设计方案中的规则和技术选择是建议，未经确认的校园规则须标注假设。若教师的新通知与本记录冲突，先记录变更来源，再更新方案和实现。

论文的系统截图、实际测试结果、部署过程及数据分析要来自后续完成的系统。当前仅能写设计目标与测试计划，不能预写“已实现”“已测试通过”或编造利用率提升数据。
